# Reactor: `React.memo` for expensive LLM work

**Reactor (`@openprose/reactor`) is a small, open-source harness for AI work that has to _keep being true_ after a chat ends.**

You declare the truths you want kept current as OpenProse **Responsibilities** -- standing goals. Reactor keeps a composed **world-model** up to date against a changing world, re-renders only the responsibilities whose inputs actually moved, and leaves a content-addressed **receipt** behind every decision.

In plain terms: you declare what should stay true, the system watches the world, and it does expensive model work **only when something material actually moved**.

## If you know React, you already know the shape

Substitute three nouns:

| React | Reactor |
| --- | --- |
| Component | **Responsibility** -- a declared standing goal |
| DOM | **World-model** -- the maintained truth, on disk, passed by pointer |
| `render()` | **A bounded LLM session** that computes the next world-model |
| props | **Subscriptions** to other responsibilities' outputs |
| `React.memo` (skip if props unchanged) | **Skip the render if subscribed inputs haven't moved** |
| Manual dependency wiring | **Forme** -- the graph wires itself from declared contracts |

The reconciler that decides _whether to wake_ is deliberately **dumb and deterministic** -- there is **no judge step**. The intelligence is frozen ahead of time, at compile, into a per-node canonicalizer and the Forme wiring. The memo key has no clock in it.

## The shape of a contract

A Reactor program is Markdown with a contract. A **responsibility** declares what it subscribes to (`### Requires`) and the truth it keeps current (`### Maintains`):

```markdown
---
name: renewal-risk
kind: responsibility
---

### Goal

Keep a current risk read on every account whose signals have moved.

### Requires

- `usage`: the per-account usage facet from the telemetry responsibility

### Maintains

A current risk score per account. Material: the score band and the top
driver per account; `fetched_at` and request ids are immaterial. Each
account carries a `valid_until`. Postcondition: every flagged account
cites a corroborating signal.
```

`### Maintains` is the world-model **schema** doing four jobs at once: it is a **type**, a **canonicalization spec** (what's material vs. immaterial, how things normalize), an optional set of **facets** (named sub-truths a consumer can subscribe to one at a time), and a set of **postconditions** that compile to commit-gate validators. The compile phase lowers it into a deterministic canonicalizer; at run time the reconciler only ever _compares_ fingerprints. The fingerprint moves iff the material content moves -- so a re-poll that returns the same truth costs nothing.

The other kinds are `gateway` (an external source -- webhook/cron/manual ingress), `function` (a called helper with `### Parameters` → `### Returns`, never a node), `pattern` (reusable coordination expanded at compile), and `test` (assertions over a subject's world-model or receipts).

## See the thesis -- keyless, no model call

The fastest way to understand Reactor is to replay a real saved run and read the per-node `rendered`/`skipped` dispositions, the cost rollup split by surprise cause, and per-node chain-verify -- with no key and no spend:

```sh
npm i -g @openprose/reactor @openprose/reactor-cli @openprose/reactor-devtools
reactor-devtools --example masked-relay --describe
```

```text
dispositions: rendered 46 · skipped 31   (reuse 32%)
cost rollup by surprise-cause: external 8 · input 69   total 77
CHAIN-VERIFY ok
```

That is "cost scales with surprise" -- checkable, with no key and no spend. From there, scaffold and inspect a project of your own, all offline:

```sh
reactor init my-project && cd my-project
reactor doctor                          # what's present + the fix for anything missing
reactor compile --check; echo "exit=$?" # offline; exits 1 if the contract set is STALE
```

To go live you set a model key and the two optional peers, then `reactor compile` to wire the DAG and `reactor serve` to drive the scaffold's static gateway to a real receipt. The [Quickstart](/cli/quickstart) walks the full path.

## Works with any harness -- Reactor is the fast path

Reactor is built on **OpenProse**: Markdown contracts that run on any Prose-Complete agent harness. The `.prose.md` contracts are harness-agnostic. Reactor itself is a real SDK + CLI + DevTools you install and run -- the deterministic host that compiles, runs, and inspects standing responsibilities, and the recommended fast path for them.

The canonical execution behavior lives in the open-source `open-prose` skill in the [`openprose/prose`](https://github.com/openprose/prose) repo. These docs are orientation; if the docs and the skill disagree, trust the skill.
